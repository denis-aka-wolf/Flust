# Архитектура Flust

## Основные принципы

1. Исходный код на Dart является единственным источником истины.
2. Dart Analyzer разбирает исходный код, а Webview использует стабильную модель виджетов Flust (Flust Widget Model, FWM).
3. Файлы `*.w.dart` по умолчанию открываются в Flust.
4. Команда `Flust: Open in Flust` позволяет открывать обычные файлы Dart без переименования или изменения их содержимого.
5. Неподдерживаемые конструкции синтаксиса должны оставаться видимыми и никогда не должны незаметно переписываться.
6. Первая версия строится на основе AST. Предпросмотр с использованием реальной среды выполнения Flutter будет добавлен на последующих этапах.

## Компоненты

- **VS Code Extension Host** — управляет жизненным циклом редактора, командами, поиском рабочей области и запуском внешних процессов.
- **Custom Editor Webview** — отображает дерево виджетов и предварительное представление разобранной модели с привязкой к исходному коду.
- **Процесс анализатора** — читает данные в формате JSON Lines из стандартного потока ввода (`stdin`) и записывает ответы в формате JSON Lines в стандартный поток вывода (`stdout`).
- **FWM (Flust Widget Model)** — модель данных для визуального редактора, не зависящая от внутренних механизмов Dart Analyzer.

## Поток обработки данных

Исходный код Dart → AST Dart → FWM → Webview.

На последующих этапах изменение свойств виджетов будет приводить к формированию точечных операций редактирования исходного кода с последующим повторным анализом.

Анализатор не должен сериализовать всё дерево виджетов обратно в код Dart.

## Объём первого этапа разработки

- Зарегистрировать файлы `*.w.dart` как документы, открываемые с помощью пользовательского редактора VS Code.
- Добавить команду `Flust: Open in Flust`.
- Реализовать разбор исходного кода и отображение дерева виджетов.
- Сохранять диапазоны исходного кода для навигации между элементами дерева и соответствующими участками кода.
- Отображать ошибки анализатора, не повреждая исходный код.
