# Протокол анализатора Flust

**Транспорт:** JSON Lines через стандартные потоки ввода и вывода (`stdin`/`stdout`). Каждая строка содержит один полноценный JSON-объект.

## Запрос

```json
{
  "id": "request-1",
  "method": "parse",
  "uri": "file:///workspace/lib/example.w.dart",
  "source": "Widget build(BuildContext context) => const Text('Hi');"
}
```

## Ответ

```json
{
  "id": "request-1",
  "ok": true,
  "model": {
    "schemaVersion": 1,
    "uri": "file:///workspace/lib/example.w.dart",
    "root": {
      "id": "node-0",
      "kind": "widget",
      "name": "Text",
      "source": { "start": 42, "end": 57 },
      "properties": {},
      "children": []
    },
    "diagnostics": []
  }
}
```

## Смещения в исходном коде

Все смещения соответствуют позициям в исходном коде Dart и измеряются в 16-битных кодовых единицах UTF-16. Такой формат соответствует смещениям, используемым Dart Analyzer и документами VS Code.

Узел модели может содержать значение `kind: "widget"` или `kind: "expression"`.

- **`widget`** — узел представляет собой вызов виджета, распознанный анализатором.
- **`expression`** — узел представляет собой синтаксическую конструкцию, которую анализатор не распознал как вызов виджета.

Начальная версия анализатора намеренно использует консервативный подход к распознаванию конструкций. Это позволяет избежать ошибочной интерпретации исходного кода и сохранить корректность данных, передаваемых визуальному редактору.
